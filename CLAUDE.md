## Architecture

**Loadoutize** is a React SPA for building and sharing game loadouts (upcoming Call of Duty Modern Warfare 4, Battlefield 6, The Finals. Delta Force, Call of Duty Warzone). It was generated from Figma Make and connects to a Supabase project.

### Frontend (`src/`)

- Entry: `src/main.tsx` → `src/app/App.tsx`
- Routes (React Router 7):
  - `/` → `GameSelector`
  - `/u/:nickname` → `UserPage`
  - `/:gameId/explore` → `GameDashboard` (public loadout feed)
  - `/:gameId/create` → `LoadoutBuilder` (requires auth)
  - `/:gameId/loadout/:loadoutId` → `LoadoutPreview`
  - `/:gameId/weapon/:configId` → `WeaponConfigPreview`
- All routes are wrapped in `AuthProvider`.
- `@` path alias maps to `src/`. Figma assets use the `figma:asset/` virtual import prefix (resolved to `src/assets/`).

### Auth (`src/providers/AuthProvider.tsx`)

Auth hits the Supabase REST API directly (no supabase-js on the frontend). The access token is stored in `localStorage` under `access_token`. Public routes pass `publicAnonKey` as the Bearer token; authenticated routes pass the user's `access_token`.

Supabase project credentials live in `utils/supabase/info.tsx` (autogenerated — do not manually edit).

### Backend (`supabase/functions/server/`)

A Deno Edge Function using the **Hono** framework. All routes are prefixed `/make-server-6db475c7/`. Persistence is the Supabase Postgres database (see `SCHEMA.sql` for table definitions), queried via `supabase-js` with the service-role key — not a KV store. JSON responses use camelCase field names (`gameId`, `userName`, `fireRate`, `imageUrl`, ...) regardless of the underlying snake_case column names; each route maps rows explicitly (see `mapLoadout` and the inline mappers in `index.tsx`) rather than doing a generic transform.

Catalog content (games, weapon categories, weapons, attachment types, attachments, perks, equipment) is managed via a self-hosted **Directus** CMS pointed at the same Postgres database — see `DATABASE_SCHEMA.md` for setup. Directus is only needed for editing; the live app and edge function have no runtime dependency on it. Uploaded images live in Supabase Storage and are resolved to public URLs by looking up `directus_files.filename_disk`.

Loadouts (user-generated) live in a single `loadouts` table with a `weapons` JSONB column and `perks`/`equipment` as `TEXT[]` — a pragmatic, non-normalized shape matching what `LoadoutBuilder.tsx` sends (embedded weapon objects, free-text perk/equipment names), not the fully-relational junction-table design `DATABASE_SCHEMA.md`'s history describes.

### UI Components

`src/components/atoms/` and `src/components/molecules/` contain shadcn/ui-style wrappers around Radix UI primitives. Prefer these over raw Radix or MUI imports.

### Game Color Theming

`src/lib/gameColors.ts` exports `getGameColor(gameId)` which returns `{ primary, light, dark, bg }` for each game. Use this consistently for per-game accent colors rather than hardcoding values.

### Atomic design structure

Follow [docs/ARCHITECTURE.md](docs/ARCHITECTURE.md). Reusable sections belong in `organisms`, page shells in `templates`, and route screens in `pages`. Keep hooks, providers, helpers, and shared types outside the component layers. Use PascalCase component filenames and explicit `@/` imports. Lower layers must not import higher layers.
